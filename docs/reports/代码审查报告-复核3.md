## 二、🟠 新回归：`set_device('cuda')` 会抛 ValueError

### 实测结果

用项目自带的 `engine-python/python/python.exe` 实机验证：

```
torch 2.11.0+cu128  cuda_available True
'cuda'    -> RAISES ValueError: Expected a torch.device with a specified index or an integer, but got:cuda
'cuda:0'  -> OK, current = 0
```

`torch.cuda.set_device()` **不接受不带索引的设备字符串**（内部 `_get_device_index(device)` 以 `optional=False` 调用，index 为 `None` 时直接抛错）。`.to('cuda')` 能接受，`set_device('cuda')` 不能 —— 这两个 API 的容忍度不一样，容易踩。

### 触发条件

三处新增的 `set_device` 都可能收到不带索引的 `'cuda'`：

| 位置 | 传入值来源 | 是否会抛 |
|---|---|---|
| `worker.py:251` | `device = args.device`，默认 `'cuda'` | ✅ 抛 |
| `flashvsr_runner.py:133` | `device = args.device if startswith('cuda') else 'cuda'`——`'cuda'` 本身就 startswith，原样透传 | ✅ 抛 |
| `seedvr2_runner.py:106` | `dev = args.device if startswith('cuda') else 'cuda:0'`——同上 | ✅ 抛 |

三处的 `startswith('cuda')` 兜底只挡非法值，**挡不住合法但无索引的 `'cuda'`**，而这恰恰是三个 argparse 的默认值。

### 实际影响面

**① `worker.py` 手动调用 —— 它自己文档里的例子就会挂**

`worker.py` 开头的 docstring 写着：

```
Spawned by the bridge like:
   python worker.py --model realbasicvsr -i in.mp4 -o out.mp4 --codec libx264 --crf 18
```

这条命令没有 `--device` → 默认 `'cuda'` → `use_cuda` 为真 → `set_device('cuda')` 抛 ValueError。顶层 `except Exception` 捕获后 `traceback.print_exc()` + `fail(str(e))` → **退出码 1**。

**② 两个 runner 独立运行 —— 上轮刚修好的入口又断了**

`python vsr_models/flashvsr_runner.py -i x -o y` 用默认 `--device cuda` → 同样抛错，且没有 try 包裹，直接未捕获 traceback。

上轮的回归是 `AttributeError`（读不存在的属性），这轮变成 `ValueError`（值格式不对）——**同一个入口，换了个方式再断一次**。

**③ 旧持久化队列的续跑（潜在，当前无实例）**

`bridge.mjs` 的 `runNext` → `spawnJob` 使用的是 `job.args`，即**创建任务时快照下来的参数数组**。在 `buildPythonArgs` 加入 `--device` 之前入队的任务，其 `args` 里没有这个参数。若这类任务留在 `cache/jobs.json` 里，重启后点"续跑"会以旧参数拉起 worker → 默认 `'cuda'` → 崩溃。

已检查：当前 `cache/` 为空（无 `jobs.json`），**暂无实例受影响**。但任何在上一版本留有队列的用户会踩到。

**④ 正式 UI 路径不受影响**

`ui/src/lib/args.ts:19` 的 `buildPythonArgs` 把 `'--device', \`cuda:${req.advanced.deviceIndex}\`` 放在基础参数数组里，无条件下发；`deviceIndex` 默认 0 → `cuda:0`。所以走界面提交的新任务始终带索引，**生产主路径是安全的**。

### 修法

在三处 `set_device` 前把无索引形式归一化。最小改动是各加一行：

```python
# worker.py:250 附近
if use_cuda:
    if ':' not in device:
        device = 'cuda:0'          # set_device 不接受无索引形式
    torch.cuda.set_device(device)
```

flashvsr / seedvr2 同理，把兜底表达式的默认分支和透传分支都收敛到带索引：

```python
# flashvsr_runner.py:132
device = args.device if ':' in str(args.device) else 'cuda:0'
# seedvr2_runner.py:105
dev = args.device if ':' in str(args.device) else 'cuda:0'
```

这样写还顺带把 `--device cpu` 之类的非 cuda 值挡在外面（原来的 `startswith('cuda')` 判断可一并简化）。

> 另一种写法是把三个 argparse 的 `default` 从 `'cuda'` 改成 `'cuda:0'`。这能覆盖"用默认值"的情形，但挡不住用户显式传 `--device cuda`，健壮性略差；建议还是在调用点归一化。

第 29 条走到现在改了 4 处文件、修了 3 轮，每轮都在"参数没传下去 → 传下去但不消费 → 消费了但入口缺参数 → 入口有参数但值格式不对"上换个位置断一次。**根因是缺少一个统一的设备解析函数** —— 三个引擎各写一遍 `args.device if ... else ...` 的兜底表达式，每次都得同步改三处，同步一次漏一次。

建议在 `worker.py` 里加一个：

```python
def resolve_device(raw):
    """把 --device 的各种写法归一成 set_device / .to() 都接受的带索引形式。"""
    s = str(raw or 'cuda')
    if not s.startswith('cuda'):
        return 'cpu'
    return s if ':' in s else 'cuda:0'
```

三个引擎统一 `device = resolve_device(args.device)`，然后 `set_device(device)`。约 8 行，之后这条线不会再断。
