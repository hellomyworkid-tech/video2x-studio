## 一、#29 已彻底关闭 ✅

没有采纳我建议的"最小修复（固定发 `cuda:0`）"，而是做了我标注为"正确做法"的完整方案。四个部分都到位：

**① 独立的 CUDA 枚举端点**（`bridge.mjs:1052`）

```js
if (route === 'GET /api/cuda-devices') {
    if (cudaDevicesCache) return send(res, 200, cudaDevicesCache);
    execFile(PYTHON_EXE, ['-c', 'import torch,json;print(json.dumps({"devices":[...]}))'],
        { timeout: 120000 }, ...)
```

缓存策略处理得细：**成功才缓存、失败不缓存**（环境可能尚未就绪），超时给到 120s（torch 冷启动约 10s）。

**② 编号空间拆分**（`args.ts:21`）

```ts
// 旗舰引擎用 CUDA 编号空间（不可复用 Vulkan 的 deviceIndex，核显机上会错位）；
// 旧持久化配置无此字段时回落 0
'--device', `cuda:${req.advanced.cudaDeviceIndex ?? 0}`
```

`?? 0` 的向后兼容是必要的 —— `localStorage` 里的旧配置没有这个字段，否则会变成 `cuda:undefined`。

**③ UI 从"骗人的提示卡"换成真下拉框**（`NewJobView.tsx:299`）

原先那张写着"旗舰引擎始终使用 PyTorch CUDA 设备 0"、同时把选择器藏起来的 `NotApplicableCard` 已删除，改为 `<AdvancedSection ... devices={cudaDevices} python bare />`。上一轮指出的"看不见的持久化配置在背后决定成败"这个问题从根上消失了。

**④ 越界的中文提示**（`worker.py:74`），三个引擎全部调用（`worker.py:281`、`flashvsr_runner.py:135`、`seedvr2_runner.py:108`）。

实机验证（本机单卡）：

```
'cuda:1' -> validate 拦截
[worker] ERROR: 本机只有 1 张 CUDA 卡（cuda:0 ~ cuda:0），无法使用 cuda:1；
                请在高级选项的 CUDA 设备中选择有效的显卡
```

原始的 `AcceleratorError: CUDA error: invalid device ordinal` 已被替换为可操作的提示。

> **一个残留边界**：`cuda:-1` 绕得过校验（`idx = -1`，`-1 >= n` 为假），落到 `set_device` 抛 `RuntimeError: Invalid device string: 'cuda:-1'`。UI 下拉框产生不了这个值，只在手动传参时可达，优先级很低。`validate_cuda_device` 里补一个 `idx < 0` 判断即可。

### 🟠 问题 1：SPyNet 的降级路径不存在，删掉权重是崩溃不是降级

`WEIGHTS_LICENSES.md` 给出的唯一一条可执行商用合规指令：

> 若要商业分发，删除 `engine-python/weights/spynet.pth` 即可，程序会自动降级
> （worker 已支持在缺失 spynet.pth 时自动降级，见 `engine-python/worker.py`）

**代码里没有这个降级。** `worker.py:284-287` 无条件传路径：

```python
model = load_realbasicvsr(
    ENGINE_DIR / 'weights' / 'realbasicvsr_x4.pth',
    ENGINE_DIR / 'weights' / 'spynet.pth',      # ← Path 对象，恒为真
    device=device, fp16=fp16)
```

`realbasicvsr.py:356` 的 `if spynet_path:` 对 `Path` 永远成立 → `torch.load()` 打开不存在的文件 → **`FileNotFoundError`**。

照着文档做商用构建的人，会得到一个启动即崩的 RealBasicVSR。

**修法很小**，而且代码本来就为 `None` 留好了路径（`if spynet_path:` 分支可跳过，第 368 行 `missing = [k for k in missing if 'spynet' not in k]` 已容忍 spynet 键缺失）：

```python
sp = ENGINE_DIR / 'weights' / 'spynet.pth'
model = load_realbasicvsr(
    ENGINE_DIR / 'weights' / 'realbasicvsr_x4.pth',
    sp if sp.exists() else None,
    device=device, fp16=fp16)
```

补充提醒：传 `None` 之后 SPyNet 权重要靠主 checkpoint 内嵌的键来填。官方 RealBasicVSR checkpoint 通常含这些键，但**这条路径没有被实际验证过** —— 若主 ckpt 不含，SPyNet 会以随机初始化运行，输出是坏的而不会报错。建议连同修复一起实测一次，或在缺失时打一条明确的 warn。

### 🟠 问题 2：`SOURCE.txt` 不存在，便携包也没配置附带它

提交信息与 README 都声称便携包附带 `LICENSE` / `NOTICE` / `SOURCE.txt`。实际核对：

| 核对项 | 结果 |
|---|---|
| 全仓库 `find -name SOURCE.txt` | **无任何文件** |
| `ui/package.json` 搜 `license` / `notice` / `source`（不区分大小写） | **零命中** |
| `f60c55e` 实际改动文件 | 只有 6 个：`NOTICE`、`README.md`、`WEIGHTS_LICENSES.md`、3 个 vendor `LICENSE` |

`electron-builder` 的 `extraFiles` 里没有任何一条把这些文件放进包内。**便携包目前不会附带 LICENSE、NOTICE 或 SOURCE.txt。**

而 README 现在写着：

> 若你拿到的是便携包（win-unpacked），包内附带的 `SOURCE.txt` 指明了对应的源码获取方式。

公开声称一件构建没有做的事，比不声称更被动。修法是在 `ui/package.json` 的 `extraFiles` 里加一条，并实际创建 `SOURCE.txt`：

```json
{ "from": "../LICENSE",  "to": "LICENSE"  },
{ "from": "../NOTICE",   "to": "NOTICE"   },
{ "from": "../SOURCE.txt", "to": "SOURCE.txt" }
```

### 🟠 问题 3：README 的源码地址指向上游仓库，不是这个分发版

README 新增节写的是：

```
git clone https://github.com/k4yt3x/video2x.git
```

这是**上游 Video2X 仓库**，其中不包含 Video2X Studio 桌面程序、`engine-python/` 三个 Python 引擎，也不包含本项目对 C++ 核心的全部改动（FilterChain / HDR / VidStab / SPAN / 解码器 flush 等）。

AGPL-3.0 §13 要求提供的是**被分发的这个修改版本**的对应源码。而本仓库的实际状态是：

```
git remote -v   → 空（无远程）
提交数          → 5（基线 281e6f1 为 squash，无上游历史）
```

这份 fork 的完整源码目前**只存在于本机**。README 里那句"完整对应源码即为本仓库内容"在本机成立，但读者拿到的 clone 地址指向的是另一个仓库。

要真正闭合这一条，需要二选一：

- **推流到一个公开可访问的仓库**（GitHub/Gitee 均可），README 与 `SOURCE.txt` 指向它；
- 或**在便携包内直接附带源码压缩包**（AGPL 也接受随对象代码一起交付源码），`SOURCE.txt` 说明其位置。

在此之前，建议把 README 那段改成不作可验证性承诺的措辞，避免公开声明与实际不符。

> 我不是律师，以上是对"文档声明与仓库/构建实际状态是否一致"的事实核对，不构成法律意见。但这三处的共同点是客观的：**文档描述的行为，代码和构建配置里都找不到对应实现。**
